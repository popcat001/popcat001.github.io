Claude Ship: Anthropic wants Claude to get your PRs merged, too

Writing code got fast. Review, fixes and sign-off did not. Claude Ship is Anthropic's attempt to close that gap.

The short version

  • Claude Ship (beta) is three agents in a row. Code Review finds and verifies problems, PR Steward fixes them and keeps CI green, and Claude Approvals decides whether Claude can approve or a human has to.
  • Approval rules live in a file in your repo, .claude/approvals.yml. You can say "docs need no human once Claude's review passes" and "billing code needs two non-authors, one from payments".
  • PR Steward never approves or merges. Your branch protection still has the final say.
  • It's for Claude Team and Enterprise on GitHub, billed by tokens, with monthly spend caps.

The problem it's aimed at

Boris Cherny, who created Claude Code, says Opus 4.5 was "the first model to write 100% of my code." Getting those changes merged is another matter. In his words, "shipping PRs hasn't caught up."

The loop is familiar. You open a pull request and move on to the next task. Review comments come back. You stop, reload the old code into your head, push a fix, wait for CI and review to run again, then go find someone to approve it.

That was tolerable when people wrote every line by hand. Now that agents write a lot of the code, approval becomes the queue everything waits in. On the Claude Code team, Claude writes most of the code, and they wanted the steps after the PR to move at the same speed. Anthropic's stated goal is to "ship code as fast as teams write it."

Three agents, one handoff

Claude Ship combines one product that's already generally available with two new betas:

Each step hands off to the next, so nobody has to babysit a PR from "opened" to "ready to merge."

Step 1: Code Review

Code Review looks at the PR from several angles with the full repository as context. It gathers candidate issues, then checks each one adversarially before it posts anything. Only confirmed findings make it onto the PR, sorted by category.

Anthropic's example is a retry helper that waits as long as the server's Retry-After header says. A simplified version of the bug:

const wait = Number(res.headers.get("Retry-After")) * 1000;
await sleep(wait); // sleep() passes wait straight to setTimeout

That header can be a number of seconds, but it can also be an HTTP date. Number() turns a date into NaN, and a missing header into 0. Either way setTimeout fires right away, so every retry goes out within milliseconds against a server that is already rate limiting you.

The review comment shows how it confirmed the bug (nothing guards against NaN or 0 before the sleep) and suggests a fix: parse both formats, and fall back to exponential backoff when parsing fails.

You can set review depth per repository to Quick, Standard or Deep.

On the Claude Code team, merged PRs more than doubled between June and September while the share of PRs that got reverted fell by over 40%. Anthropic notes that Claude's review was one layer of their process during that period, not the only change.

Step 2: PR Steward

PR Steward's job is to get the PR green and keep it there. It picks up failing CI checks, merge conflicts, and comments from Code Review, other review tools or teammates, and works through them.

By design it doesn't approve and doesn't merge. You steer it from the PR comments: @claude followed by an instruction changes what it does, and @claude stop makes it back off.

In the retry example, it first confirmed that Code Review's finding was real. Then it rewrote the parsing and fixed a test that expected a wait but never actually waited. With the push it left a comment saying Retry-After is now read as either seconds or a date, with exponential backoff when it's missing. The comment also explained how to undo the change: revert the commit, or remove the claude-pr-steward-watching label. Every check passed. Each push it makes comes with a note like that.

Step 3: Claude Approvals

Your approval policy goes in one file, .claude/approvals.yml. Anthropic's example has three rules:

PathDefaultIf Claude's review passes
Docs (docs/**)2 approvers0 humans, and Claude approves
Most code (**)2 approvers1 human still required
Billing (services/billing/**)2 humans who didn't write the PR, one of them from the payments team. Claude's review doesn't reduce this.

Rules can use Code Review's verdict, and you can also write your own classifiers in plain English. Think of it as CODEOWNERS that can read the review before deciding whether Claude signs off or a person has to.

Anthropic recommends running it in observe-only mode first. Once you trust its decisions, make it a required check in branch protection, so a PR can't merge without its green light.

How you turn it on

As a developer, type /ship in Claude Code. Claude pushes your branch, opens the PR, reviews it, and then handles feedback and failing checks. It watches that PR from your session for up to seven days, using your own usage. The session has to stay open, the machine awake, and the branch checked out. /ship stop ends it. Whether the PR can merge still depends on your permissions and the repo's branch rules.

As an admin, you can turn it on per repository so nobody has to type a command. You choose which repos, the review depth, when it runs and a monthly spend cap. Existing branch protection and required checks still apply. Claude Approvals starts working as soon as an approvals file lands on the default branch, and admins can switch it off.

The rollout Anthropic suggests is cautious: start with one repo, set a monthly cap, run approvals in observe mode, and switch enforcement on once you trust it.

How Anthropic uses it

The biggest change on the Claude Code team, according to Anthropic, is who can act on user feedback. Product managers now ship fixes themselves.

One example: users were confused by the Analytics API docs, which implied an Admin Key could pull Pro and Team usage. A PM asked Claude Tag whether anyone was fixing it, then opened a PR. Code Review found no blocking issues, a docs reviewer signed off, Claude Approvals passed it, and it merged that evening.

Availability and pricing

  • Who: Claude Team and Enterprise plans, for repositories on GitHub.
  • Billing: by tokens. Cost scales with how many PRs you have and how big they are, review depth and frequency, and how much work PR Steward does.
  • Caps: admins can set spend limits for Code Review and PR Steward. Claude Approvals has no base fee, but classifiers in your rules are billed by tokens.
  • Watch out: a rule that relies on Claude's review triggers a billed Code Review even in observe mode. /ship counts as normal Claude Code usage.
  • Not available yet for organizations using Zero Data Retention, a HIPAA configuration or customer-managed encryption keys.
  • Credits: eligible Enterprise organizations can claim at least $10,000 in Claude Ship credit. Claim it by January 15, 2027 and use it within 30 days. Terms apply.

Anthropic's own caveat applies: Claude Ship is AI, and it can miss bugs, security vulnerabilities and other problems. That's the case for keeping humans on the rules that matter, like the billing rule above.
